# Emoji grid density

Open **Search Emoji & Symbols** and choose **Zoom in** or **Zoom out** in Actions. Each step removes or adds a column. Ctrl++ (Ctrl+Shift+=) and Ctrl+− adjust the open picker. Ctrl+0 returns to its default. The selected symbol, search query and category survive reflow. Up and Down follow the rendered columns. The picker also adjusts glyph size and row height.

A fresh picker calculates its default from the available width. **Set default to … columns** remembers the current size on this device. **Use automatic grid size** clears that preference. The default is independent of favorites and copy history. On a wide grid the lower bound is six columns. Narrower grids may go down to three, and exceptionally narrow windows use as few columns as fit. The upper bound is ten, further limited by the space needed for 48 dp targets and gaps. These controls implement the density portion of #44. ### Initial grid and persistence runs

The application and test APKs for this matrix were built from `5758cf3f`. The six 100% cases passed across two whole batches. One comparison case on the earlier application, using that same test APK, failed at its expected ten-versus-nine-column assertion. The tablet went from ten to nine columns and the phone from five to four. On both, reopening the picker used the explicitly saved size.

A separate [tablet Actions capture](screenshots/emoji-density/zoom-actions.png) shows a filtered menu. A final [automatic-size capture](screenshots/emoji-density/automatic-restored.png) pairs the restored ten columns with the removed default preference. Input text was injected through Android shell commands; grid and Actions selections used taps on observed bounds. XML and pixels are sequential observations.

Both debug/benchmark app and AndroidTest builds succeeded for this matrix. The debug JVM task ran 347 cases with zero failures, errors or skips. Python passed 146 tests per mode. Each lint report contained 58 warnings and zero errors. The eleven packaged assets match the #129 app.

The same zoom workflow also passed at [200% phone font](screenshots/emoji-density/phone200-zoomed.png). This covered the exercised glyph, selection, touch dimensions and controls. Full typography and every menu item at that scale remain unverified. Across the two development stages there were twelve JUnit executions, nine passes, two intended earlier-app failures and the initial Meta+0 failure. The pointer workflow ran separately. All seven batches completed ten restoration checks and released both owners.

### Holding a zoom shortcut while opening Actions

On the API 36 tablet, holding Ctrl+Shift+= and tapping Actions transferred focus to the menu search. On the app built from `5758cf3f`, three repeat events with the modifiers released entered `===` and hid all matching actions. The repair keeps ownership of the original key sequence at the shared palette host. The host consumes repeats and key-up across the focus change, and clears its record on window focus loss or disposal.

The same AndroidTest APK exercised the earlier and repaired apps. It injected a zoom key-down with Ctrl and Shift, tapped the Actions control, verified focus in the empty editor, then injected three repeats of the same physical sequence with no modifiers. The earlier tablet failed the empty-query assertion. On the repaired tablet the search stayed empty. A distinct unmodified press after key-up entered exactly one `=`, and the picker query stayed `face`. The test used Android-injected key events and a Compose touch gesture on the Actions control. XML and screenshots are sequential captures.
